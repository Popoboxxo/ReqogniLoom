## Redis

Container: `ai-native-reqflow-poc-redis-1` (image `redis:7-alpine`)

    $ docker exec ai-native-reqflow-poc-redis-1 redis-cli ping
    PONG

    redis_version:7.4.11

`PING` -> `PONG` confirmed live. REDIS_PASSWORD is empty in `deploy/.env`, so
the compose shell wrapper omits `--requirepass` and no AUTH is expected.

Cosmetic note: `redis-cli INFO server` prints
`AUTH failed: ERR AUTH <password> called without any password configured`.
That is caused by the container's `REDISCLI_AUTH=""` env var causing redis-cli
to attempt an empty AUTH. It is harmless — `redis-cli ping` still returns
`PONG` because the server has no password. The compose healthcheck greps for
`PONG` and therefore passes. Not a defect, but it will look alarming in logs.

## Ports note

Neither `postgres` (5432) nor `redis` (6379) publishes a host port. Both are
reachable **only** from inside the Compose network. A host-side `psql` client
cannot reach them. This is intentional (compose security note: "Restrict
network access to ports 5432 and 6379"), but it means DB verification must go
through `docker exec`.
