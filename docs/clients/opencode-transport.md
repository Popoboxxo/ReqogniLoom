# OpenCode transport: Streamable HTTP on `/mcp/` for V1 and V2

> Hand-maintained artefact (not generated by `scripts/clients/render.py`).
> It records the evidence behind the `/mcp/` decision in
> `clients/registry.yaml`, so the installer, the snippets and the registry can
> be re-checked later instead of relying on a comment.

## Decision

Both OpenCode generations connect to the **canonical Streamable HTTP endpoint
`/mcp/`** with an `X-API-Key` header. OpenCode 1 uses the SSE endpoint
`/mcp/sse/` **only as a runtime fallback** when the server does not answer the
Streamable HTTP POST — that fallback is not a configuration choice, so no
shipped artifact points at `/mcp/sse/` any more. OpenCode 2 has no SSE
fallback at all.

The fallback branch described in the bugfix plan (keep V1 on `/mcp/sse/` and
select by version) is **not needed**: V1 on `/mcp/` is covered by the spike
below.

## Spike evidence (#1702, 2026-11-03)

Environment: `@opencode/cli` 2.2.5 (isolated prefix) and OpenCode 1.18.35,
against a mock MCP server — not a real ReqogniLoom instance (that follow-up is
#1703).

| OpenCode | Configured URL | `opencode mcp list` result |
|---|---|---|
| 2.2.5 | `<host>/mcp/` | **connected** (with and without `oauth: false`) |
| 2.2.5 | `<host>/mcp/sse/` | **FAILED** — `Error POSTing to endpoint … HTTP 404` |
| 1.18.35 | `<host>/mcp/` | **connected** |
| 1.18.35 | `<host>/mcp/sse/` | connected **only via the SSE fallback** (POST 404, then `GET /mcp/sse/` + `POST /mcp/sse/messages`) |

The spike also showed that both config shapes work on V2:

* V2-native `mcp.servers.reqogniloom`
* V1-form `mcp.reqogniloom` — V2 normalizes it to `mcp.servers`

That is why the installer keeps two write paths (the V2 path needs the native
shape because `opencode mcp add` cannot set `oauth: false`) while the V1
snippet stays a valid config for both generations.

Re-checked with 2.2.6: the shipped V1-form snippet, loaded in a git-rooted
project with `--standalone`, is normalized to `mcp.servers.reqogniloom` with
`url` = `<host>/mcp/`. The `{env:…}` placeholders resolve against the
OpenCode service environment, so the service must be (re)started after the
variables are set.

### Re-verified config normalization on 2.2.6

`opencode debug config` (2.2.6) against a V1-shaped document confirms:

* flat `mcp.<name>` is normalized to `mcp.servers.<name>`;
* the V1 `enabled: true` flag is normalized to `disabled: false`;
* the lowercase `permission` map is normalized to the `permissions` array;
* the V1-only top-level `subagent_depth` is **silently dropped** — see
  [opencode-v2-known-issues.md](opencode-v2-known-issues.md).

## Reproduce

```bash
# V2: native shape, Streamable HTTP
opencode mcp add reqogniloom --url "http://localhost:8001/mcp/" \
  --header "X-API-Key={env:REQOGNILOOM_API_KEY}"
opencode mcp list

# V1: same endpoint; SSE is only attempted if the POST fails
opencode mcp add reqogniloom --url "http://localhost:8001/mcp/" \
  --header "X-API-Key={env:REQOGNILOOM_API_KEY}"
opencode mcp list
```

A real-endpoint run for both binaries remains open as **#1703**.
