### Strengths

- **Action supply chain is clean**: every `uses:` across all 11 workflows is pinned to an immutable commit SHA (verified by grep: no `@vN`/`@main` references), no `pull_request_target`/`workflow_run`/`issue_comment` triggers, and the scheduled version-drift workflow validates the secret-supplied URL against SSRF/shell injection before use (`version-drift-check.yml:71-161`). Tools downloaded at runtime (uv, gitleaks, actionlint) are version- and SHA256-pinned with checksum verification (`ci.yml:159-176,1086-1096,899-902`).
- **Release supply chain is strong**: one local build is scanned by Trivy (`exit-code: 1`, CRITICAL/HIGH) and then the *same bytes* are pushed with `docker push`; the OCI revision label must equal the tag commit; SPDX SBOM, SLSA provenance, keyless cosign sign **and** verify follow (`docker-publish.yml:252-449`). `fail-fast: false` avoids half-published releases.
- **Image hygiene is mature**: both Dockerfiles are multi-stage with digest-pinned bases, patch OS packages at build time, drop build toolchains (git/gcc/pip/setups tools) from the runtime image, bake the HF model offline, and run as a non-root `app` user with a writable HOME/pid path (`backend/Dockerfile:63-251`, `frontend/Dockerfile:36-79`).
- **Fail-closed health & data gates**: `/health/ready` is a real dependency probe (503 on mandatory deps) with `/health/live` separate (`backend/reqogniloom/urls.py:36-43`); Celery worker/beat have their own probes (`docker-compose.yml:1014-1015,1116`); backups are verified with `gzip -t` + a COPY-block content gate and a non-zero one-shot status (`:372-407`), restored atomically in CI (`ci.yml:910-932`), and off-host copies are checked before destructive teardown (`deploy/check-offhost-backup.sh`).
- **Observability baseline present**: JSON logs carry a per-request id via `RequestIdMiddleware` and a `request_id` log filter (`backend/reqogniloom/settings.py:267,1575-1600`); all default services have rotating json-file logging (16 `max-size` entries); frontend proxy uses per-request DNS resolution to survive backend recreation (`frontend/nginx.conf:52-105`).
- **Test/secret gates are deliberate**: backend matrix has `fail-fast: false` and explicit path coverage (including previously dark suites), dependency audit is centralized with pinned tools and `--strict`, secret-scan gates include canaries proving rule ids are live, and nginx CSP hardening is proven with both a positive and a negative container (`ci.yml:56-198,551-724,1058-1198,950-1056`).

### Coverage gaps

- **No IaC / orchestrator beyond Compose**: no Terraform/Pulumi modules, no Kubernetes manifests, no remote locked state or drift detection anywhere in scope. ADR-08 intentionally chooses Compose for v1; the gap is that there is no *declarative* representation of host-level networking/TLS/proxy (`Caddyfile.example` is an example, not applied by any pipeline).
- **No metrics/tracing/alerting artefacts**: logs + `request_id` exist, but no Prometheus endpoint, trace exporter, dashboard definitions, alert routing, or SLO/error-budget document was found in scope. DORA signals are discussed in comments only; no measurement is collected.
- **No automated rollback path for applications**: the only documented rollback is Qdrant index-alias specific (`deploy/README.md:1282-1320`); there is no "pin previous version/digest and `up -d`" procedure, no automated canary/blue-green, and no migration reversibility check in the release pipeline. `docs/DEPLOY_RUNBOOK.md` covers Postgres restore well (§6, ADR-012) but not Honcho/Qdrant volumes (noted as residual in ADR-012/ADR-020).
- **Accepted DR residuals**: off-host dumps are gzip-only (no encryption at rest) and have no retention/pruning on the remote target (`deploy/docker-compose.offhost.yml:11-15,28-31`); off-host backups are not produced at all for the minimal stack. These are explicitly named in ADR-012, not regressions.
- **Shard balance/timeout risk (unmeasured legs)**: `backend-test` sets `-n 0` (serial) for `set-3-mcp` and `set-4-features` with the comment "Noch nicht gemessen" (`ci.yml:95-110`) under a 30-min job cap; the two largest sets are unbalanced (set-1 serial, set-2 `-n 2`), so a future growth spike can turn into a cancelled job (which hides the running test). Flaky handling exists (E2E `retries: 2`, `globalTimeout`) but no quarantine list or flake-rate metric.
- **No license/permit scanning** in `dependency-audit` — only CVE audits (`npm audit`, `pip-audit`); SBOM is generated for images but no policy gate consumes it.
- **Health-probe coverage for the frontend differs between dev and prod**, and the header smoke tests a different nginx version (OPS-001/OPS-008): there is no single test that boots the *shipped production image* and asserts both health and headers.

## PERF — Performance + Database — queries, indexes, bundles, render paths

- **Base:** `origin/main` @ `d097ef06` (read-only worktree `.tmp/wt-deep-dive/`)
- **Agents:** performance-optimizer (cross-cutting) — no source modified, no commit
- **Method:** static code analysis with order-of-magnitude arguments. No runtime profiling data was available (see Coverage gaps). Findings are worst-first.

### Scope

Backend query hot paths (`application/table_query_service.py`, `search_service.py`, `allocation_view_service.py`, `allocation_query_service.py`, `audit_service.py`, `workflow/state_reader.py`, `traceability/`, `effective_permission_service.py`, `artifact_service.py`, Celery `tasks.py` fan-out/beat sweeps); persistence indexes/constraints (`persistence/migrations/`, `persistence/models.py`); ORM usage in `rest_api/` and `mcp_server/`; DB connection settings (`reqogniloom/settings.py`); Redis cache usage; frontend bundle/import graph (`frontend/vite.config.ts`, `config/pwa-config.ts`, lazy routes, heavy viz deps); frontend render hot paths (virtualization, JSON/state work).

## 3. Methodik, Grenzen und False Positives

- Alle Reviews waren **statisch** (Read/Grep/Glob); es wurden keine Tests, Migrationen, Browser- oder Lastläufe ausgeführt. Laufzeitverhalten (z. B. APP-001 unter RLS, API-001 auf einem „proposed“ Item, L1-002 unter echter Konkurrenz) ist aus Code und Projektkommentaren abgeleitet und sollte vor dem Fix reproduziert werden.
- Wo Reviewer einen **False Positive** selbst erkannt haben, ist das dokumentiert: `EXT-003` (`httpx2`/`httpcore2` sind echte Pydantic-Pakete, kein Typosquatting) — `DEP.md` bestätigt das und eskaliert stattdessen den veralteten Lock (`DEP-001`).
- Rein stilistische Befunde wurden nach dem zweiten Review-Durchgang („adversary pass") verworfen; viele Punkte sind bereits durch Ratchets/Baselines erfasste, bewusst getrackte technische Schuld (UI-004, FE-005, FE-006) — sie sind als solche gekennzeichnet.
- Die Teilberichte wurden von 15 Spezialisten mit disjunkten Write-Sets erstellt; drei Berichte (L0, APP, API) und zwei weitere (FE, UI) fielen wegen fehlendem Datei-Tool im Subagenten an und wurden vom Koordinator wörtlich persistiert; vier Berichte (DEP, DOC, PERF, TEST) landeten über relative Pfade im Haupt-`.tmp/audit-parts/` und wurden in den Worktree kopiert.
- **Nicht abgedeckt:** produktionsnahe Messwerte (Query-Plans, `pg_stat_statements`, Bundle-Analyzer), echte Screenreader-/Geräteprüfung, IaC/Metrics/Tracing/SLOs (siehe OPS-Coverage-Gaps), vollständige Zeilen-für-Zeilen-Lektüre aller ~3200 Quelldateien (Stichproben mit Pattern-Scans).
